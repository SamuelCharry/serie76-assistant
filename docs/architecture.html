Series 76 · Arquitectura y datos

Arquitectura elegida: A+, un agente LangChain con una decisión por turno y herramientas deterministas. El LLM interpreta; el código valida y consulta; las respuestas se redactan desde SQL o desde citas literales. ADR 0001.

Flujo de un turno

ResponsabilidadQuién
Entender lenguaje informal, intención y referencias ("it")LLM (una llamada, una tool)
Canonicalizar códigos sin completarlos; fundamentar cada valor en la conversaciónCódigo (policy.py)
Fusionar seguimientos (delta) y detectar contradiccionesCódigo (policy.py)
Cifras, filtros, servicio, frecuencia, N/ASQL sobre el catálogo del PDF eléctrico
Definiciones (S4, FLA, LRA…)Tabla context_terms: texto literal del resumen + página
Redacción de la respuestaPlantillas (rendering.py); el LLM no escribe cifras

Modelo entidad–relación (PostgreSQL inspeccionado)

* = NOT NULL. Generado desde information_schema y pg_constraint. Sin pgvector: la tabla experimental de fragmentos vive solo en la instancia archivada.

Claves foráneas
  • auth_sessions → users: FOREIGN KEY (user_id) REFERENCES users(id)
  • catalog_state → imports: FOREIGN KEY (active_import_id) REFERENCES imports(id)
  • context_terms → documents: FOREIGN KEY (document_sha256) REFERENCES documents(sha256)
  • conversations → users: FOREIGN KEY (owner_id) REFERENCES users(id)
  • entries → imports: FOREIGN KEY (import_id) REFERENCES imports(id)
  • entries → source_tables: FOREIGN KEY (table_id, import_id) REFERENCES source_tables(id, import_id)
  • frequency_specs → entries: FOREIGN KEY (entry_id) REFERENCES entries(id)
  • imports → documents: FOREIGN KEY (document_sha256) REFERENCES documents(sha256)
  • messages → conversations: FOREIGN KEY (session_id) REFERENCES conversations(id)
  • service_specs → entries: FOREIGN KEY (entry_id) REFERENCES entries(id)
